# Document profiles

Brief가 문서 유형을 지정했을 때 해당 관점만 사용한다. 여러 유형이 섞이면 필요한 항목을 결합하되, 원본에 없는 관계를 만들지 않는다.

## UI·제품 명세

```text
화면·기능 ID
→ 필드와 필수 여부
→ 버튼·이벤트의 실행 조건
→ 성공·실패 결과
→ 상태·메시지·권한
```

UI 배치와 색상은 명시적으로 동작 의미가 부여된 경우에만 요구사항으로 사용한다.

## 업무 프로세스

```text
시작 조건
→ 참여자와 책임
→ 단계와 결정 지점
→ 입력·출력 문서
→ 예외·에스컬레이션
→ 완료 조건
```

순서도와 표의 단계명이 다르면 같은 단계라고 자동 병합하지 않는다.

## 정책·규정

```text
적용 대상과 범위
→ MUST / SHOULD / MAY 수준
→ 허용·금지·예외
→ 승인 권한
→ 증빙·보존·감사 조건
```

법적 의무, 내부 권고, 예시를 서로 다른 강도로 보존한다.

## 데이터·인터페이스

```text
시스템·인터페이스 ID
→ 입력·출력 필드
→ 형식·필수·기본값
→ 변환·검증 규칙
→ 오류 코드·재처리
→ 성능·보안 조건
```

Excel 수식과 데이터 검증은 계산 규칙의 증거일 수 있으나, 예시 값은 명시되지 않은 기본값으로 승격하지 않는다.
