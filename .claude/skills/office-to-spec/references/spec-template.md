# SPEC template

아래 구조를 유지하되 입력에 근거가 없는 섹션은 `원본에 명시되지 않음`으로 표시한다. 빈 내용을 추정해서 채우지 않는다.

## 작성 기준

- SPEC은 원본의 문장을 복사한 회의록이 아니라 구현·검증 계약이다.
- 요구사항의 세부 근거는 추적표에 두고, SPEC 본문은 읽기 쉬운 문장으로 유지한다.
- `confirmed`만 확정 요구사항으로 작성한다.
- `conflict`, `ambiguous`, `candidate`는 미결정 사항에서만 언급한다.
- 기능 요구사항과 인수 조건은 서로 연결되어야 한다.
- UI 구성은 업무 규칙과 분리하고, 화면에 보인다는 이유만으로 필수 동작으로 만들지 않는다.
