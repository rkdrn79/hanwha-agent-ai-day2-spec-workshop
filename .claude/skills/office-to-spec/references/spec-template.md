# General implementation SPEC template

아래 15개 공통 섹션은 구현·검증 계약의 뼈대다. 문서 프로필과 결과 언어에 따라 제목과 하위 항목을 구체화하되 번호와 핵심 의미는 유지한다. validator는 2–15번 섹션 번호를 검사하므로 제목은 번역할 수 있다. 입력에 근거가 없는 섹션은 `원본에 명시되지 않음`으로 표시하고 추정해 채우지 않는다.

## 2. 배경과 문제

## 작성 기준

- SPEC은 원본을 복사한 회의록이 아니라 구현·운영·검증 계약이다.
- `confirmed`만 확정 요구사항으로 작성한다.
- `conflict`, `ambiguous`, `candidate`는 미결정 사항에서만 언급한다.
- 한 요구사항 ID에는 한 가지 검증 가능한 의무만 둔다.
- 모든 기능 요구사항 ID가 하나 이상의 인수 조건의 `검증 대상`에 나타나야 한다.
- 표현 형식이나 시각적 배치를 근거 없이 업무 규칙으로 승격하지 않는다.
- 사용자·시스템·조직·외부 주체를 문서 프로필에 맞게 해석한다.
