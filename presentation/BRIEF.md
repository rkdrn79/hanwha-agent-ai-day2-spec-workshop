# 포함된 예제 Project → PowerPoint Brief

이 파일은 범용 `create-solution-ppt` Skill에 포함된 예제 프로젝트의 조건만 전달한다. 다른 프로젝트에서는 이 파일의 값만 바꾸고 Skill은 그대로 재사용한다.

## 목적과 청중

- 프로젝트 루트: 저장소 루트
- 목적: 완성된 솔루션의 문제·결정·동작·검증을 짧게 설명
- 청중: 프로젝트·업무 리더
- 발표 시간: 5분
- 언어: 한국어

## 결과 조건

- 슬라이드 수: 8장
- 화면비: 16:9
- 작업 폴더: `presentation/work/`
- 결과 폴더: `presentation/output/`
- 결과 파일명: `ips_wbs_solution_brief.pptx`

## 근거 우선순위

1. `docs/SPEC.md`
2. `docs/ARCHITECTURE.md`
3. `docs/adr/ADR-001.md`
4. `docs/rfc/RFC-001.md`
5. `tests/test_*.py`
6. `CHANGELOG.md`
7. 설명이 더 필요할 때만 `src/`

## 이야기 방향

```text
문제 → 결정 → 실제 동작 → 상태 흐름 → 근거 → 검증 → 결론
```

한 장에는 하나의 결론만 둔다. 제목만 읽어도 전체 이야기가 이어져야 한다.

## 시각 스타일

- 스타일 레퍼런스: `.claude/skills/create-solution-ppt/assets/lecture-style-reference.png`
- 레퍼런스의 문장·로고·고유 도형 배치는 복사하지 않는다.
- 주황은 표지·섹션·상단 제목 띠에 사용한다.
- 남색과 파랑은 파일·테스트·근거에 사용한다.
- 흰 본문, 넉넉한 여백, 남색 증거 헤더의 리듬을 유지한다.
- 같은 레이아웃을 세 장 연속 사용하지 않는다.
- 한 장의 주요 시각 객체는 두 개 이하로 둔다.
- 본문 슬라이드 제목은 22pt, 본문은 15pt, 캡션은 9pt 아래로 줄이지 않는다.

## 완료 조건

- 편집 가능한 PPTX, 전 장 렌더, contact sheet, `qa_report.md`를 만든다.
- 핵심 주장에 실제 근거 파일 위치를 연결한다.
- 레퍼런스와 contact sheet를 나란히 비교해 스타일을 검수한다.
