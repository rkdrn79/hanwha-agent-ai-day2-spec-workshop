# RoomFlow Office → SPEC QA 보고서

## Source coverage

- PowerPoint 8/8장을 확인했다.
- Excel 7/7시트를 확인했다.
- PPT 발표자 노트와 Excel 수식·데이터 검증·검토중 표시를 함께 확인했다.
- 확정 요구사항은 `PPT:S번호` 또는 `XLSX:시트!셀범위`와 연결했다.

## Traceability

- 기능 요구사항 14개와 인수 조건 7개가 `TRACEABILITY.csv`에 있다.
- 모든 `FR`과 `AC`의 상태는 `confirmed`다.
- 각 행에 실제 원본 위치와 검증 방법이 있다.
- 확정된 NFR은 없다. 조회 성능 표현은 `OPEN-004`로 남겼다.

## Conflict safety

- 조회 기간 7일/30일을 `OPEN-001`로 분리했다.
- 취소 제한 2시간/4시간을 `OPEN-002`로 분리했다.
- 예약 목적 필수/선택을 `OPEN-003`으로 분리했다.
- “빠르게”를 임의의 응답 시간으로 바꾸지 않았다.
- 취소 알림과 관리자 대리 승인을 확정 범위로 올리지 않았다.

## Testability

- 정상 예약 요청, 시간 오류, 정원 초과, 중복 예약을 Given/When/Then으로 작성했다.
- 승인 성공, 반려 사유 누락, 완료 요청 재처리를 검증한다.
- 실패 시 예약 미생성, 입력값 유지 또는 기존 상태 유지가 명시돼 있다.

## Scope safety

- 반복 예약, 출입 QR, 외부 캘린더 연동은 범위 밖이다.
- 참고 자료의 회사명·업무명·화면 ID·문구는 사용하지 않았다.
- 입력 파일은 교육용 가상 서비스 `RoomFlow`로 새로 제작했다.

## Residual risk

구현 착수 전 `OPEN-001`부터 `OPEN-006`까지 담당자 결정이 필요하다. 특히 취소 허용 시점이 정해지기 전에는 취소 버튼 조건과 `CANCEL_WINDOW_EXPIRED` 인수 조건을 확정할 수 없다.
