# ADR-001: 출고와 취소를 전체 성공 또는 전체 실패로 처리

- 상태: Accepted
- 결정일: 2026-08-13
- 결정자: 교육 실습 기준
- 관련 SPEC: `docs/IPS MVP 구현스펙.md`의 `FR-04~09`, `AC-08~12`
- 관련 RFC: `docs/RFC-001 AI 구현 범위.md`
- 대체하는 ADR: 없음
- 대체된 ADR: 없음

## 1. 맥락

출고는 재고 차감과 출고 이력 생성을 함께 수행하며, 취소는 재고 원복과 출고 상태 변경을 함께 수행합니다. 처리 도중 하나만 성공하면 재고와 이력이 불일치합니다.

2시간 MVP는 데이터베이스 트랜잭션과 SAP 연동을 구현하지 않습니다. 따라서 업무 규칙과 실행 순서만으로도 부분 변경이 생기지 않도록 단순하고 검증 가능한 정책이 필요합니다.

## 2. 결정

> 출고와 취소는 요청 수량 전체를 대상으로 하며, 모든 검증이 통과한 뒤에만 상태를 변경하는 전체 성공 또는 전체 실패 방식으로 처리한다.

- 재고 부족 시 가능한 수량만 부분 출고하지 않습니다.
- 출고 검증 실패 시 재고 차감과 이력 생성을 모두 하지 않습니다.
- 취소는 `COMPLETED` 출고의 원래 수량 전체만 허용합니다.
- 중복 취소는 추가 재고 원복 없이 실패합니다.

## 3. 검토한 대안

### 대안 A: 가용 재고만 부분 출고

- 장점: 가능한 수량을 즉시 처리할 수 있습니다.
- 단점: 잔여 요청 수량과 부분 출고 상태가 추가되며 취소 규칙도 복잡해집니다.
- 선택하지 않은 이유: 2시간 MVP의 핵심 학습 범위를 벗어납니다.

### 대안 B: 재고와 이력을 순차 수정하고 실패 시 보상 처리

- 장점: 외부 시스템이 있는 실제 분산 환경과 유사합니다.
- 단점: 보상 실패, 재시도, 멱등성 정책이 추가로 필요합니다.
- 선택하지 않은 이유: SAP·DB 없는 로컬 MVP에 과도한 구조입니다.

## 4. 결정 결과

### 긍정적 결과

- 재고와 이력의 일관성을 간단한 규칙으로 설명할 수 있습니다.
- 실패 후 불변 조건을 자동 테스트하기 쉽습니다.
- AI가 부분 처리 정책을 임의로 추가하지 못합니다.

### 부정적 결과와 감수할 비용

- 일부 수량이라도 먼저 출고해야 하는 실제 업무 요구는 지원하지 않습니다.
- 향후 부분 출고를 도입하면 상태 모델과 API 계약을 다시 설계해야 합니다.

### 후속 작업

- 부분 출고가 필요해지면 새 SPEC과 이 ADR을 대체하는 새 ADR을 작성합니다.

## 5. 검증 방법

- `AC-09`: 재고 부족 시 재고와 이력이 불변인지 검증
- `AC-10`: 중복 요청 시 추가 차감이 없는지 검증
- `AC-11`: 전체 취소 후 원래 수량으로 복구되는지 검증
- `AC-12`: 중복 취소 시 추가 원복이 없는지 검증
