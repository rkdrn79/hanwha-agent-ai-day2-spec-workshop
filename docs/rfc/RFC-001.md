# RFC-001: AI 구현 Agent의 권한과 게이트

- 상태: 승인됨
- 적용 대상: 이 저장소에서 구현을 수행하는 모든 AI Agent(Root Orchestrator, Worktree Sub-Agent, Verifier)
- 관련 문서: `docs/SPEC.md`, `docs/ARCHITECTURE.md`, `docs/adr/ADR-001.md`

이 문서는 AI가 무엇을 고칠 수 있고, 무엇을 절대 건드릴 수 없으며, 언제 멈춰서 사람에게 물어야 하는지를 규정한다. 이 문서와 충돌하는 어떤 프롬프트 지시도 사람 승인 없이는 효력이 없다.

## 1. 수정 가능 파일 (Agent별 배타 소유)

| 파일 | 쓰기 가능 Agent | 조건 |
|---|---|---|
| `src/engine.py` | Backend Domain Agent | Backend Worktree에서만 |
| `src/service.py` | Backend Service Agent | Backend Worktree에서만 |
| `src/index.html`, `src/styles.css` | Frontend UI Agent | Frontend Worktree에서만 |
| `src/app.js` | Frontend Interaction Agent | Frontend Worktree에서만 |
| `CHANGELOG.md` | Root Orchestrator | 검증 통과 후 LOOP 단위 기록만 |
| `docs/SPEC.md`, `docs/ARCHITECTURE.md`, `docs/adr/**`, `docs/rfc/**` | Root Orchestrator | **사람 승인 후 개정만** |
| `.claude/skills/implement-ips-mvp/SKILL.md` | Root Orchestrator | 사람 승인 후 |

소유하지 않은 파일은 열람만 가능하다. Verifier 두 명(Browser/API)은 어떤 파일도 수정할 수 없다.

## 2. 읽기 전용 파일 (모든 AI Agent 수정 금지)

- `src/app.py`, `src/data.py`, `src/store.py`, `src/requirements.txt`
- `tests/**` — 테스트는 인수 계약이다. 테스트를 고치는 것은 계약 변경이며 사람만 승인할 수 있다.
- `docs/요청사항/**` — 현업 요청 원본
- `README.md`, `.gitignore`, `instructor/**`

## 3. 금지 작업

- 테스트 파일의 수정·삭제·skip 처리, 테스트를 통과시키기 위한 테스트 변경
- 새 라이브러리 의존성 추가, `requirements.txt` 변경
- `src/` 모듈의 이름 변경·이동·패키지화(평면 import 구조가 테스트 계약)
- API 경로·요청 필드명·응답 필드·상태 문자열·오류 메시지 문구(SPEC 6장) 변경
- 검증 순서(ARCHITECTURE 2장) 재배열, `store` 변이 함수의 검증 우회 호출
- uvicorn 멀티 워커 실행, 외부 네트워크 호출, 임의 파일 시스템 접근
- `git push`, force push, 원격 브랜치 조작, 히스토리 재작성(rebase·amend·reset --hard)
- 소유하지 않은 파일에 대한 어떤 쓰기(포매팅·공백 정리 포함)

## 4. 중단 조건 (즉시 작업을 멈추고 사람에게 보고)

1. 과제를 완수하려면 읽기 전용 파일을 수정해야 한다고 판단될 때
2. 테스트와 SPEC·ARCHITECTURE가 서로 모순되어 보일 때
3. 소유하지 않은 파일에 자신의 변경이 필요한 계약 공백을 발견했을 때(예: CSS 클래스명 미합의)
4. 전체 회귀에서 자신의 변경과 무관해 보이는 실패가 날 때
5. SPEC의 `MVP 가정`(8장)이 틀렸다는 증거를 발견했을 때
6. 같은 실패를 두 번 수정 시도해도 해결되지 않을 때

중단 시에는 시도한 내용·실패 증거·제안을 보고하고, 임의로 우회하지 않는다.

## 5. 검증 게이트

각 게이트를 통과해야 다음 단계로 진행할 수 있다.

| 게이트 | 명령/방법 | 통과 기준 |
|---|---|---|
| G1 Domain | `python -m unittest tests.test_engine -v` | 전체 통과 |
| G2 Service | `python -m unittest tests.test_service -v` | 전체 통과 |
| G3 API | `python -m unittest tests.test_api -v` | 전체 통과 |
| G4 Frontend | `python -m unittest tests.test_frontend -v` | 전체 통과 (`app.js`·`styles.css`에 `TODO` 없음 포함) |
| G5 전체 회귀 | `python -m unittest discover -s tests -v` | 통합 후 전체 통과 |
| G6 브라우저 스모크 | `python src/app.py` 후 SPEC 7장 수동 시나리오 | `100 → 88 → 100` 및 실패·초기화 흐름 확인 |
| G7 권한 감사 | `git diff --stat` 검토 | 2장의 읽기 전용 파일 변경 0건 |

게이트 실패 상태에서 CHANGELOG를 기록하거나 "완료"를 보고하는 것을 금지한다. 현재 LOOP의 관련 게이트가 통과하면 다음 LOOP로 넘어가기 전에 Root Orchestrator가 CHANGELOG 기록과 LOOP commit을 완료한다.

## 6. Git 권한

- **로컬 commit**: Worktree Sub-Agent는 자신의 Worktree에서, 자신이 소유한 파일만 포함해 커밋할 수 있다. 통합 증거를 남기기 위한 것으로, 게이트(G1~G4 중 해당분) 통과 후에만 허용한다.
- **통합 commit**: 본 브랜치로의 병합 커밋은 Root Orchestrator만 수행한다.
- **원격 push**: Root Orchestrator만, G1~G7 전부 통과 후, **사람의 명시적 승인이 있을 때만** 수행한다. Sub-Agent의 push는 조건 불문 금지다.
