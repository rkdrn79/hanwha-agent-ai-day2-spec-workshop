# IPS WBS 출고·취소 MVP 요구사항

> 이 문서는 현업 요청이며 SPEC이 아닙니다. 구현 전에 미결정 사항을 질문하고 검증 가능한 계약으로 바꾸세요.

## 원하는 사용자 흐름

```text
WBS 재고 조회
→ 재고 선택
→ 출고 요청
→ 재고 차감·처리 결과 확인
→ 완료 출고 전체 취소
→ 재고 원복·취소 결과 확인
```

## 화면에서 필요한 것

- 자재·플랜트·저장위치·WBS·가용 재고를 조회합니다.
- WBS로 재고 목록을 필터링할 수 있습니다.
- 재고 행을 선택하면 출고 폼에 식별 정보가 입력됩니다.
- 출고 요청 번호·처리자·수량을 입력해 출고합니다.
- 성공·실패·로딩·빈 목록 상태를 구분합니다.
- 출고 이력에서 상태·수량·이동유형을 확인합니다.
- 완료된 건만 전체 취소할 수 있습니다.
- 작업 중 버튼의 중복 클릭을 방지합니다.

## 업무에서 필요한 것

- 재고는 자재·플랜트·저장위치·WBS의 조합으로 찾습니다.
- 수량이 잘못되었거나 재고가 부족하면 실패 이유를 알려줍니다.
- 같은 요청은 두 번 재고를 차감하지 않습니다.
- 실패한 요청은 재고와 출고 이력을 일부라도 변경하지 않습니다.
- 취소는 부분 수량이 아닌 원 출고 수량 전체를 원복합니다.
- 이미 취소된 건은 다시 취소하지 않습니다.

## WBS 유형별 이동유형

| WBS 유형 | 출고 | 취소 |
|---|---:|---:|
| 일반 프로젝트 | `221` | `222` |
| 가수주 | `M75` | `M76` |
| 하자보수 | `M77` | `M78` |

WBS 문자열과 유형의 연결 규칙, 미등록 유형 처리는 아직 결정되지 않았습니다.

## 데모 완료 장면

- `IM24-001` 재고 `100`을 선택합니다.
- `12`를 출고하면 `88`이 됩니다.
- 완료 이력을 전체 취소하면 `100`으로 돌아옵니다.
- 같은 요청, 재고 부족, 재취소는 실패하고 재고는 그대로입니다.

## 구현 전에 결정할 질문

- 중복 요청을 어떤 값으로 판단합니까?
- 수량 `0`과 음수는 어떻게 응답합니까?
- 재고가 없는 경우와 부족한 경우를 어떻게 구분합니까?
- 상태명과 오류 응답 형식은 무엇입니까?
- 동시 요청은 이번 MVP에서 어디까지 보장합니까?
- 전체 통과를 어떤 자동 테스트와 화면 장면으로 판정합니까?
