# 사내추첨 MVP 구현스펙

- 문서 버전: 1.0
- 상태: 승인된 교육 기준선
- 관련 문서: `docs/참고 프로젝트 분석.md`, `docs/사내추첨 MVP 기능명세.md`

## 1. 한 줄 정의

행사 진행자가 참여자 이름과 당첨자 수를 입력하면, 시스템은 입력을 정리·검증하고 중복 없는 당첨자를 무작위로 뽑아 결과와 실행 이력을 제공한다.

## 2. 범위

### 포함

- 이름 직접 입력
- 공백·빈 줄·동일 이름 중복 제거
- 당첨자 수 검증
- 중복 없는 무작위 추첨
- 테스트 시드를 통한 결과 재현
- 결과 요약과 메모리 기반 실행 이력

### 제외

- 로그인, 응모·취소, 파일 업로드
- 이벤트·기간·경품 관리
- 데이터베이스와 외부 시스템 연동
- 재추첨과 알림
- 운영 배포

## 3. 입력

| 필드 | 형식 | 필수 | 제한 | 예시 |
|---|---|---:|---|---|
| `participants` | UTF-8 문자열 | 예 | 한 줄에 이름 1명, 정리 후 최대 1,000명 | `김한화\n이태양\n박도전` |
| `winner_count` | 정수 | 예 | 1~고유 참여자 수 | `2` |
| `seed` | 정수 또는 null | 아니요 | 자동 테스트용, 화면 미노출 | `42` |

## 4. 처리 순서

1. `participants`를 줄 단위로 분리합니다.
2. 각 이름의 앞뒤 공백을 제거합니다.
3. 공백 제거 후 빈 줄을 버립니다.
4. 완전히 같은 이름은 첫 번째만 유지합니다.
5. 고유 참여자 수를 검증합니다.
6. `winner_count`의 하한과 상한을 검증합니다.
7. 고유 참여자 중 요청 인원만큼 중복 없이 뽑습니다.
8. 결과 요약을 반환합니다.
9. 성공한 추첨만 메모리 이력에 기록합니다.

## 5. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-01 | 이름의 앞뒤 공백을 제거하고 빈 줄을 제외한다. |
| FR-02 | 정리된 이름이 완전히 같으면 첫 번째만 유지하고 제거 수를 계산한다. |
| FR-03 | 영문 대소문자는 구분한다. `Kim`과 `kim`은 다른 이름이다. |
| FR-04 | 원래 처음 등장한 참여자 순서를 유지한다. |
| FR-05 | 고유 참여자에서 요청 인원만큼 중복 없이 추첨한다. |
| FR-06 | `seed`가 있으면 해당 시드를 사용하는 독립 난수 생성기로 추첨한다. |
| FR-07 | `seed`가 없으면 시스템 난수를 사용한다. |
| FR-08 | 결과에 참여자 수, 중복 제거 수, 당첨자 수, 당첨자, 추첨 시각을 포함한다. |
| FR-09 | 성공한 추첨 결과를 현재 프로세스의 메모리 이력에 기록한다. |
| FR-10 | 최근 이력은 최신 추첨부터 반환한다. |

## 6. 오류 요구사항

| ID | 상황 | 기대 동작 | 정확한 메시지 |
|---|---|---|---|
| ER-01 | 유효한 참여자가 없음 | 추첨·기록하지 않고 400 | `참여자를 1명 이상 입력해 주세요.` |
| ER-02 | 당첨자 수가 1 미만 | 자동 보정하지 않고 400 | `당첨자 수는 1명 이상이어야 합니다.` |
| ER-03 | 당첨자 수가 고유 참여자보다 많음 | 자동 보정하지 않고 400 | `당첨자 수는 참여자 수보다 많을 수 없습니다.` |
| ER-04 | 고유 참여자가 1,000명 초과 | 추첨·기록하지 않고 400 | `참여자는 1,000명 이하로 입력해 주세요.` |

검증 우선순위는 `ER-01 → ER-04 → ER-02 → ER-03`입니다.

## 7. 출력

### 정상 응답

| 필드 | 형식 | 의미 |
|---|---|---|
| `draw_id` | 정수 | 현재 실행에서 증가하는 추첨 ID |
| `drawn_at` | ISO 8601 문자열 | 추첨 시각 |
| `participant_count` | 정수 | 중복 제거 후 참여자 수 |
| `duplicate_count` | 정수 | 제거된 중복 줄 수 |
| `winner_count` | 정수 | 실제 당첨자 수 |
| `winners` | 문자열 배열 | 중복 없는 당첨자 이름 |

### 오류 응답

```json
{
  "detail": "당첨자 수는 참여자 수보다 많을 수 없습니다."
}
```

## 8. 비기능 요구사항

| ID | 구분 | 요구사항 | 확인 방법 |
|---|---|---|---|
| NFR-01 | 성능 | 참여자 1,000명 추첨을 로컬에서 1초 이내 처리 | 수행 시간 테스트 |
| NFR-02 | 재현성 | 같은 입력·당첨자 수·시드는 같은 당첨자 배열 반환 | 반복 단위 테스트 |
| NFR-03 | 개인정보 | 참여자와 결과를 파일·DB·브라우저 저장소에 저장하지 않음 | 코드·수동 검토 |
| NFR-04 | 보안 | 화면 출력 시 이름을 HTML로 직접 삽입하지 않음 | 화면 코드 검토 |
| NFR-05 | 사용성 | 오류와 주요 동작 문구를 한국어로 표시 | 브라우저 확인 |

## 9. 인수 조건

### AC-01 공백과 빈 줄 제거

```text
Given 참여자 입력이 "  김한화  \n\n이태양\n   "이고
When 입력을 정리하면
Then 고유 참여자는 ["김한화", "이태양"]이고
And 중복 제거 수는 0이다.
```

### AC-02 중복 제거와 순서 유지

```text
Given 입력이 "김한화\n이태양\n김한화\n박도전\n이태양"이고
When 입력을 정리하면
Then 고유 참여자는 ["김한화", "이태양", "박도전"]이고
And 중복 제거 수는 2이다.
```

### AC-03 영문 대소문자 구분

```text
Given 입력이 "Kim\nkim\nKim"이고
When 입력을 정리하면
Then 고유 참여자는 ["Kim", "kim"]이고
And 중복 제거 수는 1이다.
```

### AC-04 빈 입력 오류

```text
Given 입력이 공백과 빈 줄뿐이고
When 추첨을 실행하면
Then 결과와 이력을 생성하지 않고
And ER-01 메시지를 반환한다.
```

### AC-05 당첨자 수 하한 오류

```text
Given 고유 참여자가 2명이고 당첨자 수가 0이며
When 추첨을 실행하면
Then 당첨자 수를 1로 보정하지 않고
And ER-02 메시지를 반환한다.
```

### AC-06 당첨자 수 상한 오류

```text
Given 고유 참여자가 2명이고 당첨자 수가 3이며
When 추첨을 실행하면
Then 당첨자 수를 2로 보정하지 않고
And ER-03 메시지를 반환한다.
```

### AC-07 결과 무결성

```text
Given 서로 다른 참여자가 4명이고 당첨자 수가 3이며
When 추첨을 실행하면
Then winners 길이는 3이고
And 모든 당첨자는 입력 참여자이며
And 같은 이름이 두 번 포함되지 않는다.
```

### AC-08 재현 가능한 테스트

```text
Given 동일한 참여자, 당첨자 수, seed=42이고
When 두 번 추첨하면
Then 두 winners 배열이 같다.
```

### AC-09 결과 요약과 이력

```text
Given 중복 1건을 포함한 고유 참여자 3명 중 2명을 추첨하고
When 정상 완료하면
Then participant_count=3, duplicate_count=1, winner_count=2이고
And 동일한 draw_id의 결과가 최근 이력 첫 항목에 존재한다.
```

### AC-10 최대 참여자 수

```text
Given 서로 다른 유효 참여자가 1,001명이고
When 추첨을 실행하면
Then 결과와 이력을 생성하지 않고
And ER-04 메시지를 반환한다.
```

## 11. 완료 정의
