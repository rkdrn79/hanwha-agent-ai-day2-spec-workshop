# 제공 사내추첨시스템 분석과 교육 MVP 축소

## 1. 분석 대상

교육 제공 자료의 `사내추첨.zip`에는 다음 구성요소가 포함되어 있습니다.

| 구성요소 | 관찰한 역할 |
|---|---|
| `auth` | 사용자 인증과 계정 관련 처리 |
| `gateway` | 여러 백엔드 서비스의 API 진입점 |
| `event` | 이벤트, 응모, 취소, 당첨자, 재추첨 관련 핵심 업무 |
| `blockchain_gw` | 토큰·블록체인 서비스 연계 |
| `lottery-web` | 사용자용 이벤트·응모 화면 |
| `lottery-webadmin` | 관리자용 이벤트·당첨 관리 화면 |
| `api-docs` | 서비스별 API와 배포 관련 설명 |

`event` 서비스에는 이벤트·당첨 관련 DTO와 컨트롤러, 서비스, 검증기, 테스트가 있고, 사용자 웹에는 응모·취소·상세·당첨자 목록 화면이 포함되어 있습니다.

## 2. 교육용으로 그대로 사용하기 어려운 이유

- 여러 서비스와 프런트엔드를 함께 실행해야 합니다.
- 인증, 데이터베이스, 외부 연계 설정이 필요할 수 있습니다.
- 업무 규칙보다 환경 구성과 의존성 해결에 시간이 많이 듭니다.
- 2시간 안에 스펙 작성부터 검증·수정까지 완주하기 어렵습니다.

## 3. 가져올 핵심 업무 개념

전체 기술 구성을 복제하지 않고 다음 업무 개념만 사용합니다.

- 행사에 참여할 사람의 목록이 있습니다.
- 진행자는 당첨자 수를 지정합니다.
- 시스템은 유효한 참여자 중에서 중복 없이 당첨자를 뽑습니다.
- 잘못된 입력은 조용히 보정하지 않고 진행자에게 알려야 합니다.
- 추첨 결과와 실행 시점을 확인할 수 있어야 합니다.

## 4. 교육 MVP 범위

### 포함

1. 참여자 이름 직접 입력
2. 이름 공백·빈 줄·중복 처리
3. 당첨자 수 검증
4. 중복 없는 무작위 추첨
5. 결과와 요약 표시
6. 메모리 기반 최근 실행 이력
7. 핵심 규칙 자동 테스트

### 제외

1. 로그인과 사번 인증
2. 온라인 응모와 응모 취소
3. 이벤트 등록과 기간 관리
4. Excel·CSV 업로드
5. 사용자·관리자 웹 분리
6. API Gateway와 마이크로서비스 분리
7. 블록체인·토큰 연계
8. 데이터베이스 영구 저장
9. 재추첨과 당첨 포기 처리
10. 운영 배포

## 5. 교육 MVP 완료 모습

```text
진행자가 참여자와 당첨자 수 입력
        ↓
시스템이 입력 정리 및 유효성 검사
        ↓
조건이 맞으면 중복 없는 당첨자 추첨
        ↓
당첨자·고유 참여자 수·중복 제거 수 표시
        ↓
최근 추첨 실행 이력에서 결과 확인
```

## 6. 실제 시스템으로 다시 확장하는 순서

교육 MVP가 검증된 뒤 필요에 따라 다음 순서로 확장할 수 있습니다.

1. 참여자 파일 업로드
2. 이벤트 생성과 응모 기간
3. 사용자 인증과 조직 계정 연동
4. 데이터베이스 저장과 감사 이력
5. 사용자·관리자 화면 분리
6. 알림과 재추첨 워크플로
7. 필요한 경우 외부 서비스 연계

확장 단계에서도 한 번에 모두 만들지 않고 각 기능의 스펙과 인수 조건을 먼저 작성합니다.
